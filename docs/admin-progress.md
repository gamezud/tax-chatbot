## 2. ข้อตัดสินใจที่ยังมีผลกับงานต่อไป

- **ไม่ใช่ local หรือไม่ได้ตั้ง hash → 404 ไม่ใช่ 403** — ไม่บอกคนภายนอกว่ามีหน้านี้ body ต้องเท่าหน้าที่ไม่มีอยู่จริง
- **ตัวกันใช้ `before_app_request` + เช็ก path `/admin`** — `before_request` ของ blueprint ไม่ถูกเรียกเมื่อจับคู่ route ไม่ได้ (405/308 รั่ว)
- **หมายเหตุใน LINE/PDF แสดงตาม `changed_keys` ไม่ใช่ `source`** — doc ที่ค่าเท่าค่าตั้งต้นไม่ควรขึ้นว่าใช้อัตราที่ปรับ แต่ `rules_version` ยังบันทึกทุกครั้งที่ `source == "firestore"`
- **ค่าที่บันทึกมีผลหลังรีสตาร์ตเท่านั้น** — ไม่มีการคำนวณที่ได้ค่าครึ่งเก่าครึ่งใหม่ (Flask รับหลาย request พร้อมกัน และตัวคำนวณอ่าน `TAX_RULES` หลายครั้งต่อการคำนวณ)
- **ห้ามสลับ `tax_rules.TAX_RULES` ชั่วคราว** (เช่น เพื่อคำนวณภาษีตัวอย่าง) — webhook ที่เข้ามาพร้อมกันจะคิดภาษีด้วยค่าที่ยังไม่ยืนยัน
- **ฟอร์มใช้ `build_rules` ตัวเดียวกับตัวโหลด** — กฎอยู่ที่เดียว ฟอร์มกับตัวโหลดตัดสินเหมือนกันเสมอ ข้อผิดพลาดเป็น `RuleError` ที่บอกช่อง (`.field`)
- **แปลงข้อความด้วย `Decimal`** — `float("0.7") / 100` ได้ 0.006999… (ค่าในสเปก 0.5, 2.3, 5, 35 บังเอิญเท่ากัน เทสจึงต้องมี 0.7 และ 1.1)
- **อ่าน Firestore ไม่ได้ → ไม่เปิดฟอร์ม (503)** — ถ้าเติมค่าตั้งต้นแทนแล้วบันทึก ค่าที่แก้ไว้จะถูกทับ
  **แต่ doc ผิด (ตัวโหลดปฏิเสธ) → เปิดฟอร์มด้วยค่าตั้งต้นพร้อมแถบแดง** — ไม่งั้นแก้ doc ที่ผิดผ่านเว็บไม่ได้เลย `base_token` เป็นของ doc นั้น
  และบันทึกได้แม้ค่าเท่าค่าตั้งต้น (เขียนทับ doc ที่ผิด)
- **ฟอร์มส่งลายนิ้วมือของ doc (`base_token`) ไม่ใช่เลข version** — sha256 ของ doc ทั้งก้อน (ไม่มี doc = `"none"`) เทียบใหม่ใน transaction
  จับได้ทั้งแท็บเก่าและการแก้ใน Firebase Console ที่ไม่เปลี่ยนเลข version และใช้กับ doc ที่ version ผิดรูปได้
- **เลข version ใหม่ = max(version ของ active ถ้าถูกรูป, เลขสูงสุดใน `tax_rules_history`) + 1** — อ่านประวัติใน transaction ก่อนเขียน
  `rules_version` ใน `tax_history` จึงชี้ชุดกติกาเดียวเสมอ แม้ active ถูกแก้มือให้เลขต่ำลง
- **ประวัติเขียนด้วย `create` ไม่ใช่ `set`** — ถ้ามี doc เลขนั้นอยู่แล้ว (เช่น สร้างมือ) commit ล้มทั้งก้อน ตอบ 503 ไม่ทับประวัติเดิม
- **GET ไม่เขียน Firestore** (`/admin/history`, `/admin/edit?from_version=…`) — ปุ่มย้อนเป็นลิงก์เปิดฟอร์มที่เติมค่าไว้
  การเขียนมีทางเดียวคือหน้ายืนยัน → `/admin/save` → `save_config` (เทสตรวจ `commits == 0`, `begins == 0`)
- **`restored_from` จากฟอร์มเป็นแค่คำอ้าง** — อ่านเวอร์ชันนั้นใน transaction แล้วบันทึกเฉพาะเมื่อค่าตรงทุกช่อง
  ไม่ตรง (แก้ค่าหลังเติม, เลขปลอม, doc ถูกแก้) → บันทึกเป็นการแก้ปกติ ไม่ปฏิเสธ เพราะค่าผ่านการตรวจครบแล้ว
  เทียบใน route ก่อนเข้า transaction ไม่พอ (เทส `test_restored_from_compared_inside_transaction`)
- **หน้าประวัติอ่านทั้ง collection ด้วย `stream()` ไม่ใช้ `order_by` และ `limit`** — `order_by("version")` ตัด doc ที่ไม่มี field นั้นทิ้งเงียบ ๆ
  และถ้าไม่มี `order_by` แล้วใช้ `limit` จะตัดตาม doc id แบบข้อความ ("10" มาก่อน "2") · เรียงตามเลข version ใน Python
- **เวลาไทยใช้ +7 คงที่** ไม่ใช้ `zoneinfo("Asia/Bangkok")` ซึ่งบน Windows ต้องลง `tzdata` เพิ่ม (ไทยไม่มีเวลาออมแสง)
- **ซ่อนปุ่ม "ใช้ค่าตั้งต้นในโค้ด" เมื่อจะได้ "ไม่มีค่าที่เปลี่ยน" แน่นอน** (ยังไม่มี doc หรือ doc ถูกต้องและเท่าค่าตั้งต้น)
  doc ที่ตัวโหลดปฏิเสธยังแสดงปุ่ม เพราะเขียนทับด้วยค่าตั้งต้นได้
- key ที่ไม่รู้จักหรือห้ามแก้ใน Firestore → ปฏิเสธทั้ง doc · `based_on_tax_year` ต้องตรงกับ `tax_year` ของค่าตั้งต้น
- ห้ามแก้ผ่านเว็บ: `tax_year`, `expense.rental_rate.unmatched`, `deduction.parent_max_count`, `deduction.ssf_last_tax_year`
- อัตราที่ข้อความถึงผู้ใช้แสดงแบบ `:.0f` ต้องเป็นจำนวนเต็ม %: ค่าเช่า 3 อัตรา, ขายออนไลน์, อัตราขั้นบันไดทั้ง 8 ขั้น
- `secret_key` สุ่มใหม่ทุกครั้งที่เปิด — รีสตาร์ตแล้วแท็บเดิมได้หน้า "หน้านี้หมดอายุ" (400 ภาษาไทย)
- ตัวนับรหัสผิดนับรวมทั้งระบบ เก็บในหน่วยความจำ — ทุก request มาจากในเครื่อง แยกตาม IP ไม่ได้
- `pdf_generator.py` ไม่ import `tax_rules` — หมายเหตุมาเป็นข้อความสำเร็จใน `tax_data["rules_note"]`

## 3. รูปร่าง doc และ timeout

`tax_rules_config/active`
- `based_on_tax_year`: int ต้องเท่ากับ `tax_year` ของค่าตั้งต้น
- `version`: int ≥ 1 เพิ่มขึ้นทุกครั้งที่บันทึก (เลขใหม่ดูหัวข้อ 2) — ฟอร์มไม่ส่งเลขนี้ ส่งลายนิ้วมือของ doc (`base_token`) แทน
- `override`: map รูปเดียวกับ `to_override()` — ขั้นบันไดเป็น list ของ `{upper, rate}` ขั้นสุดท้าย `upper` เป็น null
- field อื่นระดับบนสุด (แหล่งอ้างอิง หมายเหตุ เวลา) ตัวโหลดไม่อ่านและไม่ปฏิเสธ

`READ_TIMEOUT_SECONDS = 10` ใน `rules_store` — ใช้ทั้งตัวโหลดและหน้า admin
- การอ่านครั้งแรกหลังเปิดโปรแกรมต้องต่อ TLS และขอ token ก่อน จึงเผื่อไว้มาก · อยู่นอกงบ 5 วินาทีของ webhook
- `get(timeout=…, retry=None)` ครอบด้วย daemon thread อีกชั้น ให้เปิดเซิร์ฟเวอร์ไม่ค้างเกินเวลานี้แน่นอน
- เวลาอ่านจริง (15 ต.ค. 2569): ยังไม่มี doc 0.53 / 0.52 / 0.54 วินาที · มี doc 0.44 / 0.46 วินาที — เผื่อไว้ราว 19 เท่าขึ้นไป คงไว้

## 5. ผลทดลองจริงที่ใช้ตัดสินแล้ว

- **header ของ ngrok** (13 ต.ค. 2569): ผ่าน ngrok `remote_addr` เป็น loopback เหมือน request ตรง ต่างกันที่มี `X-Forwarded-For`, `X-Forwarded-Host`, `X-Forwarded-Proto` ทุกครั้ง
  client ส่ง `X-Forwarded-For` เองแล้ว ngrok ต่อท้าย (ลบไม่ได้) · ปลอม Host ได้ 421 จาก ngrok ไม่ถึง Flask · user-agent แบบเบราว์เซอร์เจอหน้าเตือนของ ngrok ก่อน
- **path แปลก ๆ**: `//admin`, `///admin`, `/admin//`, `/./admin`, `/%61dmin`, `/ADMIN` ผ่าน ngrok ได้ 404 ทุกตัว
  `request.path` ของ Werkzeug ยุบ `/` ที่นำหน้าเหลือตัวเดียว ส่วน `url_map.match("//admin")` จับคู่ route ได้ — ตัวกันจึงต้องเช็ก `request.path` ไม่ใช่ `PATH_INFO` ดิบ (มีเทสล็อก)
  HEAD/OPTIONS ผ่าน ngrok ได้ 404 ไม่มี header `Allow`
- **cookie Secure บน Chrome** (13 ต.ค. 2569): ทั้ง `http://127.0.0.1` และ `http://localhost` เก็บ cookie ที่มี Secure และส่งกลับมา
- **login จริงผ่านครบ 9 ข้อ** (13 ต.ค. 2569): สร้าง hash → setx → เห็น `[ADMIN] เปิดอยู่` → login → เห็นหน้า admin → cookie มี Secure/HttpOnly/SameSite=Strict อายุ 30 นาที → logout → ผิดครั้งที่ 5 ถูกล็อก (รหัสถูกก็ได้ 429) → หน้าหมดอายุในแท็บเดิมหลังรีสตาร์ต → รีสตาร์ตแล้วตัวนับเริ่มใหม่
- **เวลาอ่าน Firestore ตอนเปิดเซิร์ฟเวอร์** (15 ต.ค. 2569, ยังไม่มี doc): 0.53 / 0.52 / 0.54 วินาที จาก log `[TAX-RULES]` 3 รอบ
  `READ_TIMEOUT_SECONDS = 10` เผื่อไว้ราว 19 เท่า — คงไว้
- **ประวัติคำสั่ง PowerShell** (15 ต.ค. 2569): ตรวจแล้ว ไม่มี hash ของรหัส admin ค้าง
- **end-to-end กับ Firestore จริง** (15 ต.ค. 2569): บันทึก version 1 (ค่าลดหย่อนส่วนตัว +10,000) → รีสตาร์ต `[TAX-RULES]` version 1 (0.44s)
  → LINE/PDF มีหมายเหตุ "(เวอร์ชัน 1)" ภาษีกรณี "ไม่มี" 7,475 ตรงกับที่คำนวณยืนยันด้วยสคริปต์แยกจากระบบ (309,500 → 299,500, ภาษี 8,450 → 7,475) → บันทึก version 2 กลับค่าตั้งต้นสำเร็จ
  (ลายนิ้วมือนิ่งเมื่ออ่าน `updated_at` จาก Firestore จริง) → แท็บที่เปิดไว้ก่อนได้ 409 และไม่มี `tax_rules_history/3`
  → รีสตาร์ต `[TAX-RULES]` version 2 ไม่ต่างจากค่าตั้งต้น (0.46s)
  → `tax_history`: รอบที่ใช้ v1 มี `rules_version` = 1 ภาษี 7,475 · รอบที่ใช้ v2 มี `rules_version` = 2 ภาษี 8,450 และ LINE ไม่มีหมายเหตุ
  (ยืนยันกับ Firestore จริงว่าบันทึกเวอร์ชันเสมอ แต่แสดงหมายเหตุเฉพาะตอนค่าต่างจากค่าตั้งต้น — ข้อตัดสินใจก้อน 3)
