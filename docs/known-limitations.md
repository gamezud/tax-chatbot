# ข้อจำกัดที่รู้แล้วของระบบ

รวมข้อจำกัดที่ตั้งใจยอมรับไว้ หรือยังไม่ได้แก้ แต่ละข้อบอกผลกระทบต่อผู้ใช้ และสิ่งที่ระบบเลือกทำ
หลักที่ใช้ตัดสินตลอดโปรเจกต์: **ตัวเลขผิดแย่กว่าให้ผู้ใช้พิมพ์เอง** — ถ้าระบบไม่แน่ใจ จะไม่เดา

ปัญหาที่มีเลขข้อ (#2, #17, #20 ฯลฯ) อยู่ใน CLAUDE.md หัวข้อ "ปัญหาที่รู้แล้ว" เลขข้อเหล่านั้นใช้อ้างในเล่มและในเทส
ที่มาทางกฎหมายของตัวเลขอยู่ใน `docs/tax-rules-2569.md`

## 1. การคำนวณและข้อสมมติทางกฎหมาย

| ข้อจำกัด | ผลกระทบ | ระบบเลือกทำอย่างไร |
|---|---|---|
| **บุตรคนที่ 2 ขึ้นไปได้ `child_second_onward` เสมอ** บอทไม่ถามปีเกิด แต่กฎหมายให้เฉพาะบุตรคนที่ 2 ขึ้นไปที่เกิดตั้งแต่ปี 2561 (docs หัวข้อ 2.2) | บุตรคนที่ 2 ขึ้นไปที่เกิดก่อนปี 2561 ได้ลดหย่อนเกิน ภาษีต่ำกว่าจริง | เป็นข้อสมมติของบอท ไม่ใช่ทางที่ปลอดภัย — ต้องเขียนในเล่ม |
| **ไม่ตรวจเงื่อนไขบิดามารดา** (อายุ 60 ปีขึ้นไป เงินได้ไม่เกิน 30,000 บาท) | ผู้ใช้ที่กรอกบิดามารดาที่ไม่เข้าเงื่อนไข ได้ลดหย่อนเกิน ภาษีต่ำกว่าจริง | เชื่อจำนวนที่ผู้ใช้กรอก ตัดที่ `parent_max_count` |
| **เงินบริจาคเกินเพดาน บอทไม่บอกว่าใช้ได้เท่าไร** ยอดบริจาคถูกตัดที่ `donation_rate` ของเงินได้หลังหักค่าใช้จ่ายและค่าลดหย่อนอื่น ซึ่งถูกตามกฎหมาย แต่สรุปผลไม่แจ้งว่าถูกตัด | ผู้ใช้เข้าใจว่าลดหย่อนได้ทั้งยอด ตัวอย่าง: เงินเดือน 40,000 บาท/เดือน ประกันสังคม 10,500 "บริจาค 102773" → ลดหย่อนรวม 101,450 ภาษี 6,427.50 (ยืนยันแล้วว่าตัวเลขถูก) แต่ผู้ใช้ไม่เห็นว่าบริจาคใช้ได้แค่ 30,950 | ตัวเลขภาษีถูกต้อง — งานค้าง: ให้สรุปผลบอก "ใช้ได้ X จาก Y บาท" พร้อมเหตุผลเพดาน (แตะสาขาสรุปผล) |
| **เงินบริจาคทุกยอดนับเป็นบริจาคทั่วไป** ไม่รองรับบริจาค 2 เท่า (การศึกษา กีฬา โรงพยาบาลรัฐ ฯลฯ) และบริจาคพรรคการเมือง (docs หัวข้อ 4) | ผู้ที่บริจาคประเภท 2 เท่าได้ลดหย่อนน้อยกว่าสิทธิ ภาษีสูงกว่าจริง | ไม่ถามประเภทการบริจาค |
| **ค่าลดหย่อนอื่นที่บอทไม่รองรับ** เช่น ประกันสุขภาพบิดามารดา ค่าฝากครรภ์และคลอดบุตร รายการใหม่ปี 2569 (docs หัวข้อ 4) | ผู้ที่มีรายการเหล่านี้เสียภาษีสูงกว่าจริง | ประกันสุขภาพบิดามารดา: ตัวกันบอกผู้ใช้ตรง ๆ ว่ายังไม่รองรับ (กรณี ง) แทนการยัดยอดเข้าช่องอื่น |
| **ขายของออนไลน์หักค่าใช้จ่ายเหมา 60% เสมอ** ตาม พ.ร.ฎ. ฉบับที่ 11 ม.8(25) (ผู้ขายไม่ได้ผลิตเอง) | ผู้ที่ผลิตสินค้าเอง หรือต้องการหักตามจริง ได้ผลไม่ตรงกับกรณีของตน | ไม่ถามว่าผลิตเองหรือไม่ ไม่รองรับหักตามจริง |
| **สิทธิทางภาษีที่ยังใช้ได้ไม่ใช่แผนภาษี** (#20) แสดงยอดที่เหลือของ RMF / ThaiESG / ประกันชีวิตตามกฎหมาย ไม่ได้คำนวณว่าควรใช้เท่าไหร่ และไม่ดูภาษีวิธีที่ 2 | ใช้สิทธิครบแล้วภาษีอาจไม่ลดเท่าที่คิด ข้อความอาจบอกว่าอยู่ในขั้นยกเว้นทั้งที่ต้องเสียตามวิธีที่ 2 | แสดงสิทธิตามกฎหมาย ไม่ใช่คำแนะนำการลงทุน |
| **ThaiESG** ตัวบทกำหนดช่วงซื้อถึง 31 ธ.ค. 2569 | ปีภาษี 2569 เป็นปีสุดท้ายที่ `thai_esg_cap` ใช้ได้ | ปีภาษีถัดไปต้องตรวจกฎกระทรวงใหม่ |

## 2. การรับค่าลดหย่อนจากแชต (Dialogflow และตัวกัน)

ตัวกัน (`utils/deduction_guard.py`) ตรวจว่าค่าที่ Dialogflow ส่งมามีหลักฐานในข้อความ ถ้าไม่มีจะปฏิเสธทั้งข้อความ ไม่แก้ค่าให้เอง

| ข้อจำกัด | ผลกระทบ | ระบบเลือกทำอย่างไร |
|---|---|---|
| **ค่าที่ถูกปฏิเสธล้างทั้งรอบ** | ผู้ใช้ต้องพิมพ์ค่าลดหย่อนของข้อความนั้นใหม่ทั้งหมด แม้บางรายการถูก | ไม่คำนวณด้วยค่าที่ไม่มีหลักฐาน และล้างค่าของรอบนั้นใน `tax_session` ไม่ให้ยอดผิดค้างไปถึงข้อความถัดไป |
| **ตัวเลขที่ไม่มีชื่อรายการนำหน้า** เช่น "ลูก 2 คน อายุ 5 ปี", "ปี 2569" | ปฏิเสธทั้งข้อความ | ตรวจย้อนกลับ: ตัวเลขทุกตัวต้องมีรายการรองรับ กันยอดหายเงียบ (แบบ #23 ที่ยอดประกันชีวิตหายแล้วภาษีสูงเกินจริง) |
| **"ประกัน" คำเดียวถือเป็นประกันชีวิต** | ถ้าผู้ใช้หมายถึงประกันประเภทอื่น ยอดจะถูกนับเป็นประกันชีวิต | เป็นข้อสมมติ — ประกันรถ ประกันภัย ประกันอุบัติเหตุ ประกันอัคคีภัย ประกันบ้าน เป็นคำที่ไม่นับ |
| **ดอกเบี้ยบ้านรับเฉพาะคำที่รู้จัก** ("ดอกเบี้ยบ้าน", "ดอกเบี้ยเงินกู้บ้าน", "ดอกเบี้ยกู้บ้าน" ฯลฯ) "ดอกเบี้ยสินเชื่อบ้าน" ไม่นับ | ผู้ใช้ได้ข้อความให้พิมพ์ใหม่ | ไม่รับ "ดอกเบี้ยเงินกู้" เฉย ๆ เพราะอาจเป็นกู้รถ (#25) และไม่รับ "ผ่อนบ้าน" เพราะรวมเงินต้น |
| **"กองทุนรวมเพื่อการออม" (ชื่อเต็มของ SSF) ไม่อยู่ในรายการคำ** | ได้ข้อความให้พิมพ์ใหม่ แทนหมายเหตุว่า SSF ลดหย่อนไม่ได้แล้ว | ยอดไม่ถูกนับ ซึ่งถูกต้องเพราะ SSF ลดหย่อนไม่ได้ตั้งแต่ปีภาษี 2568 |
| **หมายเหตุ SSF ขึ้นแม้ผู้ใช้พิมพ์ว่า "ไม่มี SSF"** | ได้ข้อความเกินมาหนึ่งบรรทัด | ไม่กระทบตัวเลข |
| **ข้อมูลหายเมื่อผู้ใช้เงียบเกิน 20 นาที** Dialogflow ลบ context เอง | ผู้ใช้กลับมาพิมพ์ตัวเลขต่อ บอทไม่รู้ว่ากำลังถามอะไรอยู่ และไม่ได้แจ้ง | งานค้าง: แจ้งผู้ใช้เมื่อ context หมดอายุ |

## 3. การอ่านหลักฐานการบริจาคจากรูป (OCR / หน้า LIFF)

ผลวัดความแม่นและรายละเอียด: `docs/ocr-eval-2569-10.md`

| ข้อจำกัด | ผลกระทบ | ระบบเลือกทำอย่างไร |
|---|---|---|
| **ผลวัดมาจากรูปสังเคราะห์** ไม่ใช่ภาพถ่ายจริง | ความแม่นกับรูปจริงน่าจะต่ำกว่าผลวัด | ตัวชี้วัดหลักคือ confident wrong (ตอบ ok แต่ผิด) ซึ่งเป็น 0 ในชุดวัด |
| **ยอดที่เป็นเลขไทยได้ `thai_digits`** | ผู้ใช้ต้องพิมพ์ยอดเอง แม้ OCR บางครั้งอ่านถูก (ใบอนุโมทนาบัตร ๓,๕๐๐ บนมือถือ) | ไม่เชื่อเลขไทย เพราะชุดวัดอ่านยอดเลขไทยถูก 0/42 รูป และผิดแบบที่ดูเป็นตัวเลขปกติ |
| **ใบเสร็จแบบตารางหลายรายการ** (ยอดแต่ละรายการไม่มีคำว่าบาท) | ได้ `ambiguous` ผู้ใช้ต้องพิมพ์เอง | ตัวเลขรูปแบบเงินนอกบรรทัดเงินที่ค่าไม่เท่ายอด ทำให้ไม่ตอบ ok |
| **OCR อ่านหลักหาย** (15,000 → 5,000) แล้วผลยังดูปกติ | parser ตรวจไม่ได้ อาจได้ ok ด้วยยอดผิด | หน้า LIFF แสดงรูปข้างช่องยอด เตือนให้เทียบ และผู้ใช้ต้องกดส่งเอง |
| **OCR อ่านคำบริจาคไม่ออก** (รูปไกล/เล็ก) | ใบบริจาคได้ `not_donation` (ชุดวัด: 7/210 รูป ส่วนใหญ่คือรูปย่อ 50%) | ไม่ส่งยอดจากรูปที่ยืนยันไม่ได้ว่าเป็นการบริจาค |
| **คำที่ไม่นับเป็นคำบริจาค:** "สมทบ" (ชนกับเงินสมทบประกันสังคม), "มูลนิธิ" / "วัด" (เป็นชื่อผู้รับ) | ใบบริจาคที่มีแต่คำเหล่านี้ได้ `not_donation` | คำบริจาคที่หลวมทำให้เงินอื่น (เช่น เบี้ยประกัน) ถูกนับเป็นเงินบริจาค |
| **การหมุนรูปตาม EXIF ยังไม่ได้ทดสอบกับรูปที่ EXIF หมุนจริง** | ถ้าเบราว์เซอร์ไม่หมุนให้ รูปตะแคงจะอ่านไม่ได้ | ทดสอบบนมือถือ Android ซึ่งบันทึก Orientation 1 ทุกรูป |
| **ต้องเปิดหน้า LIFF ในแอป LINE** | เปิดนอกแอปใช้งานไม่ได้ | หน้าแสดงข้อความให้เปิดในแอป LINE บนมือถือ หรือพิมพ์ยอดในแชตเอง |
| **อ่านได้ทีละรูป** | ผู้ใช้ที่ส่งพร้อมกันได้ข้อความให้ลองใหม่ | OCR ใช้ CPU เครื่องเดียวกับ webhook ถ้าอ่านพร้อมกันหลายรูป webhook อาจเกินงบ 5 วินาที |

## 4. ความเป็นส่วนตัวและความปลอดภัย

| ข้อจำกัด | ผลกระทบ | ระบบเลือกทำอย่างไร |
|---|---|---|
| **ลิงก์ดาวน์โหลด PDF ไม่ตรวจสิทธิ์** (#17) | ใครได้ลิงก์ก็เปิด PDF สรุปรายได้ได้ (ชื่อไฟล์สุ่ม 8 hex) | — ยังไม่แก้ |
| **log ของเซิร์ฟเวอร์พิมพ์ LINE user ID และยอดเงิน** (เพื่อดีบัก) | ใครเห็นหน้าจอเซิร์ฟเวอร์เห็นข้อมูลผู้ทดสอบ | log ของ `/liff/ocr` ไม่พิมพ์ข้อความจากรูปและยอด — ต้องปิด log อื่นก่อน demo (CLAUDE.md) |

## 5. คำถามความรู้ภาษี (RAG)

| ข้อจำกัด | ผลกระทบ | ระบบเลือกทำอย่างไร |
|---|---|---|
| **index ค้นไม่เจอ chunk ที่ถูกสำหรับบางคำถาม** (วัดที่ k=2): "ยื่นภาษีใช้เลขอะไร", "กอช. ลดหย่อนได้เท่าไหร่", "ภาษีขั้นบันไดคิดยังไง", "ภาษีหัก ณ ที่จ่ายคืออะไร" | คำตอบไม่ตรงคำถาม | การแก้ต้องปรับ `chunk_size` / `k` ซึ่งเป็นงานแยก |
| **ฐานความรู้ไม่ครอบคลุมทุกข้อ** ข้อความใน `tax_knowledge.txt` ที่ไม่มีใน docs ไม่ได้ตรวจกับปี 2569 (เช่น กองทุนสำรองฯ 15%, ภ.ง.ด.94, ผ่อนชำระ 3 งวด, อัตราหัก ณ ที่จ่าย) | ข้อความเหล่านี้อาจไม่ตรงกับปีภาษี 2569 | ตัวเลขที่ใช้คำนวณภาษีอยู่ใน `utils/tax_rules.py` และตรวจกับ docs แล้ว ไม่ได้มาจากฐานความรู้ |
| **LLM อ้างผิดว่า ThaiESG ลดหย่อนตาม "มาตรา 47"** (#22) | ที่มาทางกฎหมายในคำตอบผิด ตัวเลขถูก | LLM เรียบเรียงถ้อยคำเท่านั้น ไม่คำนวณเลข — ยังไม่แก้ |
