# ประโยค holdout — ห้ามใช้เป็น training phrase

ประโยคในไฟล์นี้ใช้**ทดสอบ** Dialogflow หลังแก้ training phrase ห้ามเพิ่มเป็น training phrase บน Console
ทั้งแบบตรงตัว และแบบที่มีประโยคนี้อยู่ข้างในประโยคที่ยาวกว่า

> เหตุผล: ถ้าใส่ประโยคที่เจอบั๊กลง training แล้วทดสอบด้วยประโยคเดิม ผลผ่านไม่ได้พิสูจน์ว่า Dialogflow แยกได้จริง
> มันแค่จำประโยคนั้นได้ (แผนแก้ #23 รอบแรกเคยถูกตีกลับเพราะทำแบบนั้น)

## ขั้นตอนแก้ training phrase (ใช้กับ #23–#26)

1. เขียนเทสใน `tests/test_dialogflow_export.py` ที่ตรวจ export ปัจจุบันแล้วล้ม ติดป้าย `xfail(strict=True)` แล้ว commit
2. เตรียมสองรายการแยกกัน: **ประโยคที่จะเพิ่ม** และ **ประโยค holdout** ที่ไม่อยู่ในรายการแรก
   - ตัวเลขทุกตัวในประโยคที่จะเพิ่มต้อง annotate และมีชื่อรายการอยู่ระหว่างตัวเลขก่อนหน้ากับตัวเลขนั้น
     ยกเว้นตัวเลขหลังคำที่ตั้งใจไม่นับ (SSF, ประกันสังคม ฯลฯ) — ไม่งั้น `test_numbers_after_keywords_are_annotated`
     และ `test_training_phrases_pass` (ตัวกันปฏิเสธประโยคที่สอนเอง) ล้ม
   - แนวปฏิบัติ (เทสไม่ได้บังคับ): ใช้ตัวเลขไม่ซ้ำกันภายในประโยคเดียว เพื่อให้อ่านค่า parameter ใน log ตอนทดสอบใน LINE
     ได้ว่ายอดไหนเข้าช่องไหน
3. เจ้าของโปรเจกต์เพิ่มประโยคบน Console → export agent ลง `dialogflow/` → ถอดป้าย xfail ใน commit เดียวกับ export
4. ทดสอบประโยค holdout ใน LINE ตรวจค่า parameter ใน log และภาษีเทียบกับ `utils/tax_calculator.py`
5. holdout ที่ล้มด้วยเรื่องที่ไม่เกี่ยวกับบั๊กที่กำลังแก้ จดเป็นข้อจำกัดหรือปัญหาใหม่ ไม่ขยายงานรอบนั้น
6. เพิ่มประโยค holdout ใหม่ลงไฟล์นี้

ประโยคที่ใช้ตรวจว่าตัวกันปฏิเสธถูก (ประโยคตรวจ) ก็ห้ามใช้สอนเช่นกัน
