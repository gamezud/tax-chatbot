## #38 คำตอบค่าเช่าที่ได้ Fallback ทำให้ผู้ใช้ค้าง

- **อาการ (ระหว่างทดสอบ #37):** "ค่าเช่าบ้าน 120,000" และ "บ้าน 120000" ตอนมี `awaiting_rental` ได้ `Default Fallback Intent`
  ข้อความตกสาขาความรู้ ผู้ใช้ไปต่อได้เฉพาะเมื่อคำตอบถัดไปบังเอิญได้ `03` ก่อน `awaiting_rental` (lifespan 2) หมดอายุ
  พ้นจากนั้นต้องพิมพ์ "เริ่มใหม่"
- **หลักฐาน:** fixture 023 · fixture 008 ("คอนโด 120000") เคยได้ `03` ด้วย confidence 0.719 ขณะที่ `mlMinConfidence` คือ 0.6
  training phrase ของ `03` ไม่เปลี่ยนตั้งแต่ export แรก (9 ประโยค)
- **วิธีแก้:** Fallback + `awaiting_rental` + ไม่มี `awaiting_online` / `awaiting_deduction` + มีตัวเลข → `handle_rental_fallback`
  ยอดจาก `clean_number(user_query)` แบบสาขาออนไลน์ ประเภทจาก `find_property_word` (รายการคำเดียวกับ `get_rental_expense_rate`)

  | ข้อความ | ผล |
  |---|---|
  | มีคำบอกประเภท ยอดมากกว่า 0 | บันทึกแบบสาขา 03 |
  | ไม่มีคำบอกประเภท ยอดมากกว่า 0 (เช่น "120000") | ถามซ้ำ เปิด `awaiting_rental` ต่อ ไม่ใช้อัตราของกรณีที่ไม่รู้จัก |
  | ยอด 0 และไม่มีเลข 1-9 ("0", "บ้าน 0") | ไปต่อ ป้ายเป็นคำที่เจอ หรือ "ไม่มีค่าเช่า" |
  | ยอด 0 แต่มีเลข 1-9 ("บ้าน ปี 2569") | ถามซ้ำ (`clean_number` ตัดปีทิ้ง ผู้ใช้ไม่ได้ตอบว่า 0) |

- **ปัญหาที่พบระหว่างแก้และยังไม่แก้:** #39 (entity `PropertyType`), #40 (ยอดจาก `clean_number` ในสาขาสำรอง)
  และบรรทัด "หักค่าใช้จ่ายเหมา (30%): 0.00 บาท" เมื่อไม่มีค่าเช่า (`docs/known-limitations.md` หัวข้อ 1)

## ทาวน์โฮม (b1385cd)

"ทาวน์โฮม" มีใน entity `PropertyType` แต่ไม่อยู่ในรายการคำ เดิมได้ 30% จากกรณีที่ไม่รู้จัก และสาขาสำรองจะถามซ้ำ
หลังแก้อยู่กลุ่มโรงเรือน อัตราของข้อความที่มีแค่ทาวน์โฮมยังเป็น 30%
แต่ "ที่ดินพร้อมทาวน์โฮม" เปลี่ยนจาก 15% เป็น 30% แบบเดียวกับ "ที่ดินพร้อมบ้าน" (#2)
